b Bank · MVP Prototype

Dashboard & Check Balance

A clickable prototype of the MVP feature. The controls beside the phone switch it between the states described in the user stories — so acceptance criteria can be seen rather than read.

9:41

Prototype controls

Each control maps to a story in the backlog. Use them in a review to walk stakeholders through the edge cases, not just the happy path.

US-07 · Localization

Language

Switches every label, tile and error message. Bangla mode also renders Bangla numerals — one of the open questions to settle.

US-01 · Balance privacy

Hidden by default

The balance opens masked. Tap it to reveal, tap again to hide. Leaving the Dashboard and coming back re-hides it — the revealed state never persists.

US-03 · Failure states

Balance retrieval

Note that a failed balance never shows as ৳0.00, and never blocks the tiles below it.

US-05 · Conditional tiles

Eligibility

Fund Transfer and Bangla QR are gated. The treatment toggle answers the open question — hide the tile, or show it disabled with a reason?

US-06 · Promotional carousel

Banner scope

Targeted carousel served from the configuration service. With one eligible banner it degrades to a static card; with none, the area collapses.

Notes for the build team. The banner endpoint is mocked as an ordered list already filtered for this customer — the app never receives campaigns it isn't entitled to show, so targeting stays server-side and Phases 2–3 need no app rework. Balance is read once per screen entry and on pull-to-refresh; nothing is cached across sessions. All state here is in-memory: state in the script block, safe to host as a static page.
